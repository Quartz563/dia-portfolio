Case Study

Graph Visualiser

A Java desktop application that generates random connected weighted graphs and uses two pathfinding algorithms to locate the shortest path. This project was written to understand how the two algorithms differ, and Maven was added later to accommodate the unit tests using the JUnit suite which found two bugs in how the connections formed.

Generating a connected graph

A randomly generated graph is only useful for pathfinding if every node can be reached. Rather than generating edges at random and checking connectivity afterwards, the generator builds the graph one node at a time so that it is connected at every step:

  1. Each new node is joined to a randomly chosen node already in the graph. This forced connection guarantees that the graph stays connected.
  2. The new node is then offered a connection to every other node in the graph. The chance of each connection starts at 90% and falls by 10 percentage points for every connection the two nodes already have, to a minimum of 10%. This spreads connections across the graph instead of letting a few nodes become hubs.
  3. A final pass gives any node with fewer than two connections another one to another random node, so that there is usually more than one route between two nodes and the algorithms have a choice to make.

Pathfinding

Dijkstra's algorithm

Dijkstra's algorithm expands nodes in order of their distance from the start, using a priority queue, and records each node's predecessor so the path can be rebuilt once the destination is reached. It always finds the cheapest path, but explores in every direction.

A* search

A* orders the queue by distance travelled plus an estimate of the distance remaining, using the straight-line distance between nodes as the estimate. This steers the search towards the destination and explores fewer nodes. It only finds the cheapest path if the estimate never exceeds the real remaining cost, which turned out to matter.
